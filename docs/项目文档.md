## 1. 架构

```

┌──────▼──────────────┐

```

## 3. 数据模型

### products

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Integer | 主键 |
| name | String(100) | 型号，严格等于基准目录写法 |
| category | String(20) | gpu / cpu / memory / ssd |
| brand | String(50) | 品牌 |
| specs | String(500) | 显卡存 TSE 跑分，CPU 存 R23，内存/硬盘存每 GB 价格 |
| current_price | Float | 最新价 |
| change | Float | 最新价相对前一天的涨跌额（元） |
| change_pct | Float | 涨跌百分比 |
| platform | String(20) | jd / taobao / pdd / douyin / xianyu |
| condition | String(10) | new / used |
| lowest_shop | String(100) | 今日最低店铺（内存/硬盘） |
| lowest_model | String(100) | 今日最低型号（内存/硬盘） |

唯一约束：`(name, platform, condition)`。

### price_history

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Integer | 主键 |
| product_id | ForeignKey | 关联产品 |
| price | Float | 当日价格 |
| change | Float | 当日涨跌额 |
| change_pct | Float | 当日涨跌百分比 |
| date | Date | 精确到天 |
| platform | String(20) | 平台 |

写入规则：同一天、同一产品、同一平台只保留一条，重复采集则更新。

### 设计说明

- 单表存四品类，靠 `category` 区分。四类字段 90% 重合，查询以跨品类列表为主，分表会让查询和工具层都要写多套分支。
- 平台与成色分离。闲鱼是二手渠道，混进平台维度会让比价把二手价当成全新最低价。
- `change` 同时存在产品表和历史表。产品表服务于列表页，避免每次遍历历史；历史表服务于趋势图。

## 4. 数据流与参数

| 环节 | 参数 | 说明 |
|---|---|---|
| 抽帧 | `fps=1/3` | 每 3 秒一帧，720P |
| 去重 | 汉明距离 ≤ 3 | 低于阈值视为同一画面 |
| 视觉分批 | 2 张/批 | 一批最多两张表，避免输出触达上限 |
| 视觉模型 | `doubao-seed-2-1-lite-260915` | `temperature=0.1`，`max_tokens=2500`，关闭 thinking |
| 截断重读 | 结尾为 `...` 或长度 ≥ 2500×95% | 该批改为逐帧单独重读，单帧只含一张表 |
| 文本截断 | 8000 字符 | 送给抽取模型的识图文本上限 |
| 抽取模型 | `deepseek-chat` | 注入型号目录，要求原样选择 |
| 异常阈值 | 千元以上相对偏离 30%；千元以下绝对 500 元或相对 50% | 超阈值不入库；若"今价−视频涨跌"贴近基准则放行 |
| 浮动告警 | 1000 元 | 与上次价格差超过则打 WARNING |
| 入库日期 | 视频发布日期 | 补跑往期不覆盖 `current_price` |
| B站请求间隔 | 2 秒/次 | 命中 `-352` 风控按 5/15/30 秒退避重试 |
| 抽帧容错 | 3 次尝试，间隔 5 秒 | ffmpeg 带 `-reconnect`，单次超时 300 秒；仍失败则整期放弃，不降级缩略图 |
| 旁白归档 | `video_digests` 表 | 按 `bvid` 唯一，存当日价格归纳 + 硬件新闻（JSON） |

## 5. 关键设计决策

### 5.1 用视频而不是爬虫

电商页面结构多变、反爬严格，维护成本高。固定 UP 主的日报表格结构稳定，识图一次即可拿到全平台价格。

代价：依赖单一数据源，需要抽帧与视觉调用成本。

### 5.2 视觉只负责转写，结构化交给文本模型

两个模型各自可替换、可单独测试。视觉提示词只要求"照抄表格"，文本模型负责 JSON 结构。出错时能定位到是读错还是解析错。

### 5.3 一行一个型号

旧格式"型号|平台|价格"会让模型在 60 多行输出中沿用上一行型号，导致相邻型号合并。改成一款型号一行、四个平台同排后，输出降到 16 行，型号只写一次，消除了"忘记切换型号"的空间。

### 5.4 型号严格匹配目录

型号名有前缀关系（4080 / 4080 S / 5070 Ti S），模糊匹配会互相抢数据。改为白名单：目录里没有就跳过并告警，宁缺勿错。

### 5.5 品类与成色正交

`category` 表示"是什么"，`condition` 表示"新旧"，`platform` 表示"在哪买"。三者组合才能准确描述一条价格。

### 5.6 幂等

产品层三列联合唯一，历史层按天先查后写。重跑同一期不会产生重复数据。

### 5.7 关闭视觉模型的深度思考

doubao 默认开启 thinking，`max_tokens` 会被 reasoning 全部消耗，正文返回空串。读表格不需要推理，直接关闭。

| `DATABASE_URL` | 数据库连接 | `sqlite:///./diy_agent.db` |

## 8. 运行与验证

```bash
# 初始化（会清空数据）
python seed_data.py

# 采集一期
python -m app.crawler.bilibili_pipeline --videos 1 --before 2026-11-17 --no-asr

# 批量多期
python -m app.crawler.bilibili_pipeline --videos 10 --interval 3

# Cookie 过期时扫码刷新（自动写回 .env）
python -m app.crawler.bilibili_login

# 启动服务
uvicorn app.api:app --reload
```

验证分四层：

1. 帧级：先确认第几秒是什么表
2. 组件级：复用已抽帧单独测视觉与抽取，不重复下载
3. 链路级：跑一期端到端
4. 数据级：核对型号数、日期、平台、重跑幂等

排障与回归标准见 [错题本](错题本.md)。

## 9. 已知限制

| 限制 | 影响 |
|---|---|
| 只验证过 2 期视频 | 阈值与提示词的稳定性未经长期检验 |
| 启用了 `--no-asr` 为主 | 音频转写链路未与价格表联合验证 |
| 基准价仍是 2025-11-17 行情 | 异常检测基准偏旧 |
| 行号跨表连续 | 暂无法按表做行数校验 |
| SQLite 单机 | 未做并发与多实例验证 |
| seed 会生成 30 天模拟历史 | 仅用于演示，真实采集后应避免覆盖真实日期 |
