# 采集链路错题本（写给后续 AI）

这不是给人看的复盘，是给后续修改本项目的 AI 看的操作约束。

**读取时机**：修改 `app/crawler/**`、`app/db/**`、`seed_data.py`、`app/data/benchmark_prices.json` 之前，先读完本文件，改完执行第六节的回归清单。

**使用方式**：第一节是不变量，动了就会出脏数据；第三节是排障决策表，出现症状直接照做，不要重新推导。

---

## 一、不变量

破坏任意一条，都会直接产生错误数据。修改前先确认不会碰到这些。

1. **视觉输出一行一个型号**：格式 `行号|型号|平台=价格/涨跌幅|...`，同一型号的所有平台必须在同一行。禁止退回"一个平台一行"的格式——那会让模型在长序列里沿用上一行型号，把相邻行合并。
2. **平台只能是五个**：`jd`、`taobao`、`pdd`、`douyin`、`xianyu`。其他一律丢弃，不允许 `unknown` 入库。
3. **型号严格匹配目录**：只接受 `benchmark_prices.json` 里存在的名字，不做模糊匹配、不新建产品。目录里没有就跳过并打 WARNING。
4. **成色与平台分离**：闲鱼只能对应 `condition=used`，其余平台 `condition=new`。唯一键是 `(name, platform, condition)`。
5. **入库日期来自视频发布日期**，不是 `date.today()`。补跑往期不能覆盖 `current_price`。
6. **视觉模型必须关闭深度思考**：`extra_body={"thinking": {"type": "disabled"}}`。否则 `reasoning_tokens` 会吃光 `max_tokens`，正文返回空串。
7. **无货、看不清不能写成 0**：视觉侧输出"无货"或"?"，入库前跳过。
8. **抽帧默认 3 秒**，并保留 dHash 去重。抽帧间隔必须小于最短表格停留时长。
9. **视觉单批最多两张截图、输出上限 2500 字**：一批里塞进三张表（内存 + CPU + 闲鱼）时，模型写到上限会把最后一张表整段截断，且不会报错。`BATCH_SIZE = 2`；检测到输出以 `...` 结尾或长度接近上限时必须逐帧重读。
10. **抽帧失败不许降级到 videoshot 缩略图**：缩略图只有 360px，`15999` 会被读成 `8999`，错价还会覆盖库里正确数据。只能重试 ffmpeg，重试仍失败就放弃这一期。

## 二、禁止操作

| 禁止 | 后果 | 替代做法 |
|---|---|---|
| 用型号名做模糊/包含匹配 | 4080 与 4080 S、5070 与 5070 Ti 互相抢数据 | 目录严格匹配 |
| 把闲鱼塞进 `platform` | 比价把二手价当成全新最低价 | 用 `condition` 区分 |
| 用 `date.today()` 记录往期视频 | 同一期数据散落在多个日期 | 传视频发布日期 |
| 让视觉模型输出纯 JSON | 密集表格下容易漏行、格式失败 | 先输出带行号的文本行，再交给文本模型结构化 |
| 只看一帧就判断"视频没有价格表" | 漏掉真正的价格表 | 先建立全片画面地图 |
| 在 `save_price` 里用 `result` / `data` 命名局部变量 | 覆盖外层结果，写报告时 `KeyError` | 用具体名字 |
| 用 `DateTime` 存按天数据 | 一天散成几十个时间戳 | 用 `Date` |

## 三、症状到动作

| 症状 | 判断 | 立即动作 |
|---|---|---|
| 视觉接口 200 但内容为空 | 大概率 thinking 吃光配额 | 检查 `extra_body` 是否关闭 thinking，再打印 `reasoning_tokens` |
| 抽取条数为 0 | 先分清是"没读到"还是"没解析" | 看报告里的「截图识别结果」原文 |
| 出现 `platform=unknown` | 天梯图/跑分榜被当成价格表 | 确认平台白名单生效 |
| 同一型号同一平台出现两次 | 视觉阶段合并了相邻行 | 检查 `FRAME_PROMPT` 是否被改回"一平台一行" |
| 某型号整行消失 | 同上 | 看行号是否断档 |
| 型号末尾 S/Ti 丢失 | 密集小字 OCR 不稳定 | 检查提示词第 5 条与 `_normalize_name` |
| "型号不在目录中"告警变多 | 抽取模型在改写字号 | 确认抽取提示词里有型号目录 |
| 一天出现多个时间戳 | 日期字段类型错了 | 确认 `models.py` 用 `Date` |
| 真实日期里混入随机价格 | seed 模拟历史越界 | 模拟历史只能早于首期采集日 |
| 二手价比全新价还"便宜"地排第一 | 成色未分离 | 检查 `condition` 条件是否进入查询 |
| CPU 型号带 `/KF` 却全部被跳过 | 归一化改写了型号名 | 检查 `_normalize_name` 的斜杠规则，只处理两侧带空格的斜杠 |
| 某一天条数远少于其他天（如二手 12 条 vs 39 条） | 视觉输出触达字数上限，尾部整张表被截断 | 看报告末尾是否有 `37...` 这类省略；确认 `BATCH_SIZE=2` 且截断重读生效 |
| 某条真实价格被"排除异常" | 基准价只代表基准日，当天真实大涨被判成偏高 | 用视频涨跌幅还原昨价再比；不要直接放宽阈值 |
| 日志出现 `code=-352` | 请求过于频繁被 B站风控 | 确认所有请求都走 `_get`，不要直接 `session.get` |
| 日志出现 `TLS ... -10054` 或 ffmpeg 长时间无输出 | B站 CDN 直链断连，非代码问题 | 已内置 ffmpeg 断点重连 + 3 次重试（间隔 5 秒）；不要改回 videoshot 兜底 |

## 四、错误档案

完整叙述见 Git 历史；这里只保留排查所需的因果链。

| 编号 | 错误 | 根因 | 修复 | 回归验证 |
|---|---|---|---|---|
| 1 | 视觉返回空字符串 | doubao 默认开 thinking，max_tokens 被 reasoning 吃光 | 关闭 thinking，max_tokens=1500 | content_len > 0 |
| 2 | 误判视频没有价格表 | 只看第 7 帧（股票表） | 逐帧建立画面地图 | 0/20/40 秒分别有表 |
| 3 | 35 条 unknown 平台 | 天梯图数字被当成价格 | 平台白名单 | unknown 为 0 |
| 4 | 型号漏 S 串号 | 密集小字 + 前缀型号 | 提示词点名 + 目录严格匹配 | 4080 S=8374、4080=7599 |
| 5 | 5050 整行并入 5060 | 一平台一行导致自回归沿用上型号 | 改为一型号一行 + 行号 | 显卡 16 行全齐 |
| 6 | 16G/16GB 拆成两型号 | 单位写法不统一 | 基准表统一 GB，归一化补 B | 型号数与目录一致 |
| 7 | Super 写法导致严格导入跳过 | 模型补全缩写，目录用 S | 目录注入提示词 + Super→S | "不在目录中"为 0 |
| 8 | 一天散成 61 个时间戳 | DateTime 存了完整时间 | 改 Date + `date.today()` | 同天同产品同平台一条 |
| 9 | 同期数据落两个日期 | 补跑用 today() | `save_price(record_date=...)` | 落在发布日期 |
| 10 | 模拟历史混入真实日 | seed 生成 30 天随机值 | 模拟历史截止到首期采集日前 | 真实日条数=抽取条数 |
| 11 | 闲鱼价当第五平台 | 平台与成色压成一维 | 新增 `condition` | 新旧价互不影响 |
| 12 | 5090 重复产品 | 模糊匹配失败后新建 | 严格匹配目录 | 产品数不增长 |
| 13 | KeyError: 'title' | 局部变量 `result` 覆盖外层 | 改名 | 报告正常生成 |
| 14 | 整张表漏采 | 10 秒间隔大于表格停留时长 | 默认 3 秒 + 去重 | 四张表都覆盖 |
| 15 | 1 秒采样时 127 帧只去重到 47 帧 | dHash 阈值 3 偏严，轻微动画和压缩噪点被判成新画面 | 回到 3 秒采样，阈值待调参 | 3 秒下无异常 |
| 16 | JSON 解析 KeyError | 模型返回带 markdown 标记 | 剥离代码块 + 正则兜底 | 抽取恢复 |
| 17 | 把返回空误判为 token 不足 | 没看 token 明细 | 先看 `reasoning_tokens` | —— |
| 18 | CPU 型号 `/KF` 被归一化改坏 | 斜杠归一化把任意 `/` 换成空格 | 只替换两侧带空格的斜杠 | `U7-265K/KF` 能命中目录 |
| 19 | 11-20 那期二手只入库 12 条 | `BATCH_SIZE=4` 时一批含内存 + CPU + 闲鱼三张表，输出触达 1500 字上限，最后一张表被模型截断且不报错 | 批大小 4→2、上限 1500→2500、检测到截断（结尾 `...` 或长度 ≥ 95%）改为逐帧重读 | 11-19 二手从 12 恢复到 39 |
| 20 | RX 9070 京东 6989 元被误判异常排除 | 基准价是 11-18 的 5289，当天真实涨 1800 后被判偏高 32.1% | `check_anomaly` 接收视频涨跌幅，用"今价 - 涨跌"还原昨价再比，贴近基准则放行 | 带涨跌放行、无涨跌仍拦截 |
| 21 | 重跑连续触发 `code=-352` 风控 | 根因是 `.env` 里的 Cookie 已过期（nav 返回 `isLogin=False`），程序实际在匿名请求；短间隔又放大了触发概率 | 启动时 `check_login()` 自检并告警 + 请求间隔 2 秒 + 5/15/30 秒退避 | 过期时启动即提示，退避后能取到列表 |
| 22 | 11-18 数据被错价覆盖（5090D 读成 16999、5080 读成 8999 等） | ffmpeg 拉流 TLS 断连后静默降级到 360px 的 videoshot 缩略图，低清图上数字 OCR 必错，且错价"看着正常"能过异常检测 | 取消缩略图兜底：ffmpeg 失败重试 3 次（间隔 5 秒，并加 `-reconnect`），仍失败则整期放弃，绝不写价格 | 日志出现「抽帧 3 次失败」时该期无新数据，库里旧值不变 |

## 六、回归清单

改动采集链路后必须执行，不能只看代码。

```bash
python -m app.crawler.bilibili_pipeline --videos 1 --before 2026-11-17 --no-asr
```

通过标准：

1. 帧去重日志形如 `42 -> 30`
2. 提取条数约 120-130 条
3. 日志中 `型号不在目录中` 为 0
4. 日志中 `同型号重复` 为 0
5. 报告「截图识别结果」里显卡表为 01-16，每行四个平台齐全
6. 抽查 `RTX 5050`、`RTX 5060` 四平台价格互不相同且各自正确
7. 数据库日期等于视频发布日期，不是运行当天
